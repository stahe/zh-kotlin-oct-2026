    14. 延伸阅读

    本文介绍了 Kotlin 语言，以及在 Java 虚拟机上编写分层应用程序、网络客户端和服务器以及 Web 服务时最常用的库。下面是在此基础上进一步深入的主要主题。

    14.1. 处理 XML 文档

    JSON 已在很大程度上取代 XML 用于数据交换，但 XML 仍在使用（配置文件、文档格式、现有的 SOAP 服务）。Kotlin 直接使用 JDK 的 XML API，位于 [javax.xml] 包中：

    • DOM （[DocumentBuilder]、[Document]、[Element]）：文档作为树被加载到内存中，然后对其进行遍历和修改；
    • StAX （[XMLStreamReader]、[XMLStreamWriter]）：文档被即时读取或写入，而无需完整加载到内存中；
    • XPath （[javax.xml.xpath]）用于查询文档，XSLT （[javax.xml.transform]）用于转换文档。

    除了 JDK 之外，Jackson 还可以通过其 [jackson-dataformat-xml] 模块读写 XML，就像处理 JSON（第 5 章）那样；JetBrains 的 kotlinx.serialization 库在编译时生成序列化代码，它也支持由社区开发的 XML 格式。

    14.2. Web 应用程序

    第 13 章只涵盖 Web 服务（生成数据的应用程序）。对于生成 HTML 页面的 Web 应用程序，或在 Kotlin 中编写 Web 服务的其他方式，可以使用下列方案：

    • Spring MVC 搭配 Thymeleaf 之类的模板引擎：服务器端生成页面。Spring 对 Kotlin 的支持与对 Java 一样（数据类、控制器中的协程、用 Kotlin 配置路由）；作者撰写了课程 《Spring Web 框架分步入门》（2026 年 9 月）；
    • Ktor，JetBrains 的 Web 框架，用 Kotlin 编写并为 Kotlin 而生：基于第 9 章的协程构建的 HTTP 服务器和客户端，使用 Kotlin 代码而不是注解来配置；
    • 其他支持 Kotlin 的 JVM 框架：Quarkus、Micronaut、Javalin，以及 Jakarta 应用服务器 EE；
    • 用 JavaScript 编写的、消费 Kotlin Web 服务的界面（Vue.js、Angular、React）；作者撰写了课程 《Vue.js 框架分步入门》（2026 年 9 月）。Kotlin 本身可以编译为 JavaScript（Kotlin/JS）或 WebAssembly（Kotlin/Wasm），这也使客户端可以用 Kotlin 编写。

    14.3. 移动和桌面应用程序

    本文不涉及图形用户界面：如今，管理类应用程序大多使用 Web 界面构建。不过，这是 Kotlin 被广泛使用的领域：

    • 在 Android 上，Kotlin 是 Google 推荐的语言，UI 使用 Jetpack Compose 构建，这是一个完全用 Kotlin 编写的声明式库；协程（第 9 章）用于在网络或数据库访问期间保持 UI 的响应性；
    • Compose Multiplatform，由 JetBrains 推出，扩展了 Compose，可用同一套代码编写桌面（Windows、Linux、macOS）、iOS 和 Web 界面；
    • 更一般地说，Kotlin Multiplatform 允许在 JVM、Android、iOS（通过 Kotlin/Native，它无需虚拟机即可生成机器码）和 Web 之间共享业务逻辑代码（例如第 6 章中的 [business] 和 [dao] 层）；
    • 在 JVM 上，Java 的 Swing 和 JavaFX 库仍然可以在 Kotlin 中使用。第 7 章（事件监听器）和第 9 章（用 [Dispatchers.Main] 回到 GUI 线程）所讲的概念在这里可以直接应用。

    14.4. 测试

    第 6 章介绍了 JUnit 和 [kotlin.test]。它们通常还会辅以：

    • Kotest，一个为 Kotlin 编写的测试框架，提供多种测试编写风格和丰富的断言库（[list shouldHaveSize 7]）；
    • MockK，为 Kotlin 设计（支持 final 类、对象、挂起函数）的“模拟对象”（mock，即模拟出来的对象）库，用于模拟被测层所依赖的各层；Mockito 仍然可以使用；
    • kotlinx-coroutines-test，使用虚拟时钟对基于协程的代码运行测试：[delay(10_000)] 会立即执行完毕；
    • Testcontainers，在集成测试期间，在 Docker 容器中启动一个真实的数据库（MySQL、PostgreSQL……）；
    • Spring Boot 测试工具（[@SpringBootTest]、[MockMvc]），用于在不部署的情况下测试 Web 服务。

    14.5. 性能

    Kotlin 程序由 Java 虚拟机（JVM）执行：它受益于即时编译和运行时优化，性能与 Java 程序相当。在更进一步的工具中：

    • JMH 工具（“Java Microbenchmark Harness”），可以直接在 Kotlin 中使用，或通过 kotlinx-benchmark Gradle 插件使用，在考虑虚拟机预热的情况下精确测量代码性能；
    • JDK Flight Recorder 和 JDK Mission Control，用于记录和分析程序在生产环境中的行为；IntelliJ IDEA 包含性能分析器和协程调试器；
    • 使用 GraalVM Native Image 进行提前编译为本机代码：得到一个几毫秒即可启动的独立可执行文件，代价是对反射有所限制；Spring Boot 和 Quarkus 可以从 Kotlin 代码生成这样的可执行文件；
    • 垃圾回收器的选择（默认为 G1，对于大内存堆需要极短停顿时则用 ZGC）。

    14.6. 部署

    Kotlin 程序的部署方式与 Java 程序一样：作为 [.jar] 归档文件，由机器上安装的 JDK 执行（[java -jar application.jar]），前提是包含 Kotlin 标准库（由 [gradlew installDist] 生成的脚本就是这样做的，第 2 章；Spring Boot 生成包含其所有库的独立 [.jar] 文件）；或作为内嵌了一个仅保留所需内容的精简虚拟机的独立应用程序（JDK 的 [jlink] 和 [jpackage] 工具）；或在 Docker 容器 中（Spring Boot 通过 [gradlew bootBuildImage] 直接生成容器镜像）。

    14.7. 资源

    • Kotlin 官方网站，提供文档、教程以及每个版本的“新增内容”页面： https://kotlinlang.org；
    • 在线沙盒 Kotlin Playground，用于在浏览器中试用 Kotlin 代码；
    • 练习 Kotlin Koans ，可在 Kotlin 网站和 IntelliJ IDEA 中使用；
    • 语言演进提案（KEEP），用于了解即将发布的版本中的新内容： https://github.com/Kotlin/KEEP；
    • 编译器和标准库的源代码，可在 GitHub 上获得：https://github.com/JetBrains/kotlin，以及协程的源代码： https://github.com/Kotlin/kotlinx.coroutines；
    • Java API SE 25 的文档，用于在 Kotlin 中使用的 JDK 类：https://docs.oracle.com/en/java/javase/25/docs/api/；
    • 图书 *Kotlin in Action*（Manning）和 Marcin Moskała 的 *Effective Kotlin*，以及关于 JVM 并发的 Brian Goetz 等人所著的 *Java Concurrency in Practice*（Addison-Wesley）。
