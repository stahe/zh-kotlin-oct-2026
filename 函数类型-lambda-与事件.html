    7. 函数类型、lambda 与事件

    在许多程序中，我们需要向函数传递的不是数据，而是行为：排序标准、过滤条件，或者在某件事发生时要执行的动作。Kotlin 通过把函数当作与其他值一样的值来满足这一需求：函数具有类型——即函数类型，例如记作 [(Int, Int) -> Int]；它可以存储在变量中、作为参数传递、作为另一个函数的结果返回，并在需要时随时执行。接受或返回函数的函数称为高阶函数。

    提醒一下，Java 没有函数类型：它依赖于函数式接口——只有一个抽象方法的接口（[Runnable]、[Comparator]、[Function<T, R>]……），直到 Java 8（2014 年）才允许使用lambda 表达式 和方法引用来实现它们。Kotlin 从第一个版本起就支持 lambda，而且由于它直接使用 Java 库，所以也能使用 Java 的函数式接口。我们在第 5 章介绍的集合操作中已经大量使用了 lambda，只是没有深入细节：在 [persons.filter { it.age >= 18 }] 中，我们向函数 [filter] 传递了一个 lambda。本章解释这种语法背后的原理。本章最后讲述事件，Kotlin 与 Java 一样，使用“监听器”来处理事件：监听器是向发射器注册的函数（大多是 lambda），用于接收那里发生之事的通知。图形用户界面（Swing、JavaFX、Compose）和 Web 框架都依赖于这一机制：按钮点击或 HTTP 请求的到达会通知给已注册的监听器。本课程不涉及图形用户界面；所有示例都是控制台程序。

    本章的程序组织在 Gradle 项目 [07-lambdas] 中，每个程序一个包：[src/main/kotlin/lambdas01/Lambdas01.kt]、[src/main/kotlin/lambdas02/Lambdas02.kt]……。它们通过 [gradlew -q run -Pmain=lambdas01.Lambdas01Kt] 运行，或者在 IntelliJ 或 IDEA 中点击绿色三角形运行。该项目除标准 Kotlin 库之外不需要任何库：函数类型、lambda 和作用域函数都已包含在内，而 [java.util.function] 包中的接口与 JDK 中的相同。

    7.1. 函数类型与预定义的函数式接口

    7.1.1. 函数类型的概念

    函数类型 描述函数的模型（也称为签名或形式）：括在括号中的参数类型，后面跟一个箭头，然后是返回值的类型。函数类型的变量可以引用任何这种形式的函数并执行它。下面是几个例子：

    • [() -> Unit]：没有参数、不返回有用结果的函数（[Unit] 的作用相当于 Java 的 [void]）；
    • [() -> String]：没有参数、返回字符串的函数；
    • [(Int) -> Boolean]：接受一个整数并返回布尔值的函数，换句话说，就是谓词；
    • [(Int, Int) -> Int]：接受两个整数并返回一个整数的函数；
    • [(String) -> (Int) -> Int]：接受一个字符串并返回……一个类型为 [(Int) -> Int] 的函数的函数（箭头从右向左读）；
    • [(() -> Unit)?]：可能不存在的函数；括号是必需的，因为 [() -> Unit?] 否则表示返回 [Unit?] 的函数。在这里我们看到了第 3 章中与 [null] 相关的安全特性：这样的函数用 [f?.invoke()] 表示；
    • [String.(Int) -> String]：带接收者的函数；它作用于一个字符串——其代码中用 [this] 表示——就像扩展函数一样（第 4 章）。它既可以作为扩展来调用（["ab".f(3)]），也可以作为以接收者为第一个参数的普通函数来调用（[f("ab", 3)]）。

    可以给参数命名，以便为类型提供说明：[(n1: Int, n2: Int) -> Int] 与 [(Int, Int) -> Int] 是同一个类型。

    获得函数类型的值有三种方法：

    • 编写对具有正确形式的现有函数的引用：[val task: () -> Unit = ::display]；
    • 编写 lambda 表达式：[val task: () -> Unit = { println("task") }]；
    • 编写匿名函数：[val task = fun() { println("task") }]，或者使用实现该函数类型的类的对象（函数类型是一个接口，我们稍后会看到）。这两种写法不太常见。

    然后，函数像普通函数一样执行：[task()]。这是调用函数对象的方法 [invoke] 的简写形式：[task.invoke()]。这是与 Java 的第一个明显区别，在 Java 中你必须按名称调用接口的方法（[run]、[apply]、[test]……）；Kotlin 在这里的行为与 C# 相似，在 C# 中委托像方法一样被调用。

    7.1.2. Kotlin 函数类型与 java.util.function 接口

    在 Java 8 之前，每个 Java 库都定义自己的单方法接口（[Runnable]、[Comparator]、[ActionListener]……）。Java 8 引入了 [java.util.function] 包，它提供了 43 个泛型函数式接口。Kotlin 不需要它们：函数类型可以直接书写。不过，这些接口仍然可以在 Kotlin 中使用，而且每当你调用 Java 库时都会遇到它们。下表给出了主要的 Java 接口与 Kotlin 函数类型之间的对应关系：

    在 Kotlin 中，函数类型可以拥有的参数数量没有实际限制：[(Int, Int, Int) -> Int] 的写法与其他类型一样简单，而在 Java 中，由于没有预定义的三参数接口，你必须自己定义。

    只认识类和接口的 Java 虚拟机如何表示函数类型？通过 Kotlin 库中的泛型接口：[kotlin.jvm.functions.Function0<R>]、[Function1<P1, R>]、[Function2<P1, P2, R>]……一直到 [Function22]，再往后是接口 [FunctionN] 。每个接口都只有一个方法 [invoke]：[(Int, Int) -> Int] 被编译成 [Function2<Integer, Integer, Integer>]，其方法是 [operator fun invoke(p1: Int, p2: Int): Int]。正是 [operator] 修饰符（作用于 [invoke] ，参见第 4 章的运算符重载）使得 [f(2, 3)] 这种写法成为可能。因此，对 JVM 来说，函数类型就是一个像 Java 中那样的函数式接口。由于 Java 泛型只适用于对象类型，[Int] 值在传给 [(Int, Int) -> Int] 时会被转换为 [Integer] ，反之亦然（装箱 和拆箱）。Java 通过其专门的接口（[IntBinaryOperator]……）避免这些转换；Kotlin 则以另一种方式避免它们，即使用 [inline] 函数，我们稍后会讨论。

import java.util.function.IntBinaryOperator
import java.util.function.Predicate
import java.util.function.Supplier

// Kotlin 函数类型和 Java 函数式接口

fun main() {
    // 1 - () -> Unit：没有参数，没有结果
    val task: () -> Unit = ::display
    // 执行：函数像普通函数一样被调用
    task()
    // 这是调用其 invoke 方法的简写
    task.invoke()

    // 2 - (Int, Int) -> Int：两个参数，一个结果
    val operation: (Int, Int) -> Int = ::add
    println("operation(2, 3)=${operation(2, 3)}")
    // () -> String：没有参数，一个结果
    val greet: () -> String = ::greet
    println("greet()=${greet()}")

    // 3 - (String) -> Unit：一个参数，没有结果
    val write: (String) -> Unit = ::println
    write("(String) -> Unit executed println")

    // 4 - (Int) -> Boolean：谓词
    val isEven: (Int) -> Boolean = ::isEven
    println("isEven(8)=${isEven(8)}")
    val numbers = mutableListOf(3, 8, 1, 6, 5, 4)
    // Kotlin 库的 removeAll 期望一个 (Int) -> Boolean
    val modified = numbers.removeAll(isEven)
    println("even numbers removed: $modified, remaining: $numbers")

    // 5 - 由函数构建的 Comparator<T>（Java 接口）（SAM 转换）
    val names = mutableListOf("Paul", "Mélanie", "Jo", "Sébastien")
    names.sortWith(Comparator(::compareLengths))
    println("sorted by length: $names")

    // 6 - java.util.function 接口仍然可用
    val supplier: Supplier<String> = Supplier(::greet)
    val multiply = IntBinaryOperator(::multiply)
    val predicate = Predicate<Int> { it > 4 }
    println("supplier.get()=${supplier.get()}")
    println("multiply.applyAsInt(2, 3)=${multiply.applyAsInt(2, 3)}")
    // removeIf 是 Java 方法（Collection）：它期望一个 Predicate
    val values = mutableListOf(10, 3, 8, 7, 2, 1)
    values.removeIf(predicate)
    // Kotlin 函数会被自动转换为 Predicate（SAM 转换）
    values.removeIf(isEven)
    values.removeIf { it == 1 }
    println("after removeIf: $values")

    // 7 - 可空函数类型：函数可能不存在
    execute(null)
    execute(task)

    // 8 - 带接收者的函数类型：String.(Int) -> String
    val times: String.(Int) -> String = String::repeat
    println("\"ab\".times(3)=${"ab".times(3)}, times(\"cd\", 2)=${times("cd", 2)}")

    // 9 - 函数是对象，是实现某个接口的类的实例
    println("class: ${operation::class.java.name}")
    println("interfaces: ${operation::class.java.interfaces.contentToString()}")
    val sum: (Int, Int) -> Int = { n1, n2 -> n1 + n2 }
    println("class of the lambda: ${sum::class.java.name}")
    println("interfaces: ${sum::class.java.interfaces.contentToString()}")
}

// 接收可能不存在的函数的函数
fun execute(callback: (() -> Unit)?) {
    // 安全调用：如果 callback 为 null，则什么也不执行
    callback?.invoke()
    println("callback ${if (callback == null) "absent" else "present"}")
}

// 被引用的函数：文件的顶层函数

    println("display() executed by task()")
}

fun add(n1: Int, n2: Int): Int = n1 + n2

fun multiply(n1: Int, n2: Int): Int = n1 * n2

fun greet(): String = "Hello"

fun isEven(n: Int): Boolean = n % 2 == 0

fun compareLengths(s1: String, s2: String): Int = s1.length.compareTo(s2.length)

    7.2. 定义自己的函数类型

    函数类型通常已经足够，但你可能希望给某个函数模型起一个名字。Kotlin 为此提供了两种工具，它们在本质上差别很大。

    第一种是类型别名，使用关键字[typealias]声明：

    • [typealias BinaryOperation = (n1: Int, n2: Int) -> Int]

    别名不会创建新类型：[BinaryOperation] 是[(Int, Int) -> Int]的另一个名字，这两种写法可以互换。当函数类型很长或频繁出现时，别名可以使代码更易读。

    第二种是函数式接口，通过[fun interface]声明：

    • [fun interface Operation { fun calculate(n1: Int, n2: Int): Int }]

    这完全等价于 Java 的函数式接口：只有一个抽象方法的接口（也称为SAM，即“Single Abstract Method”接口）。它也可以有带方法体的方法和非抽象属性，这些不计入其中。位于[fun] 之后的[interface] 与 Java 注解[@FunctionalInterface]作用相同，但有一个重要区别：它不是可选的。正是这个关键字启用了SAM 转换，即从 lambda 或函数引用创建 [Operation]对象：[Operation { n1, n2 -> n1 + n2 }]。如果没有关键字[fun]，Kotlin 接口即使只有一个方法，也只能由类或匿名对象（[object : Operation { … }]）来实现。

    与类型[(Int, Int) -> Int]相比，类型[Operation] 是真正的新类型，与其他所有类型都不同：它有一个描述其用途的名字，它的方法有一个具有描述性的名字（[calculate] 而不是[invoke]），它可以有额外的方法，并且可以由具名类来实现。反过来，它是通过方法名来执行的（[op.calculate(2, 3)]），而不是[op(2, 3)]。

    名为[op] 、类型为[Operation]的变量，与类型为[(Int, Int) -> Int]的变量一样，一次只能引用一个函数。与提供“多播委托”的 C# 不同，Java 和 Kotlin 都没有提供在单个变量中存储多个函数并通过一次调用执行它们全部的方式：需要时，我们把这些函数存储在列表中，再逐个执行。我们处理事件监听器时正是这样做的。

    val op2 = Operation(g)

// 从匿名对象到 lambda 表达式

fun main() {
    // 1 - 匿名对象：就地编写实现函数类型的类
    val add = object : (Int, Int) -> Int {
        override fun invoke(n1: Int, n2: Int): Int {
            return n1 + n2
        }
    }
    println("anonymous object: add(2, 3)=${add(2, 3)}")

    // 2 - 用 lambda 表达式做同样的事：{ parameters -> body }
    val subtract = { n1: Int, n2: Int -> n1 - n2 }
    println("lambda with typed parameters: subtract(2, 3)=${subtract(2, 3)}")

    // 3 - 参数类型由期望的类型推断
    val multiply: (Int, Int) -> Int = { n1, n2 -> n1 * n2 }
    println("lambda with untyped parameters: multiply(2, 3)=${multiply(2, 3)}")

    // 4 - 单个参数：无需命名，此时称为 it
    val square: (Int) -> Int = { it * it }
    val isEmpty: (String) -> Boolean = { s -> s.isEmpty() }
    println("square(7)=${square(7)}, isEmpty(\"\")=${isEmpty("")}")

    // 5 - 没有参数：没有箭头
    val greet = { "Hello" }
    val beep = { println("beep!") }
    println(greet())
    beep()

    // 6 - 由多条语句组成的函数体：最后一个表达式的值就是结果
    val repeat: (String, Int) -> String = { text, times ->
        val buffer = StringBuilder()
        for (i in 1..times) {
            buffer.append(text)
        }
        buffer.toString()
    }
    println(repeat("ab", 3))

    // 7 - 未使用的参数：_
    val listener: (Any?, String) -> Unit = { _, _ -> println("event received") }
    listener(null, "click")

    // 8 - 作为参数传递的 lambda：如果它是最后一个参数，则放在括号之外
    val numbers = mutableListOf(3, 8, 1, 6, 5, 4)
    val evens = numbers.filter { it % 2 == 0 }
    println("evens: $evens")
    numbers.sortWith { n1, n2 -> n2.compareTo(n1) }
    println("descending order: $numbers")
    // lambda 在括号之外，位于其他参数之后
    val total = numbers.fold(0) { acc, n -> acc + n }
    println("total: $total")

    // 9 - lambda 中的 return：return@label 只退出该 lambda
    numbers.forEach {
        if (it % 2 == 0) return@forEach
        print("$it ")
    }
    println("<- odds")
    // 由开发者选择的标签
    numbers.forEach odd@{ n ->
        if (n % 2 != 0) return@odd
        print("$n ")
    }
    println("<- evens")
    // 匿名函数：其中的 return 退出该匿名函数
    val isLarge = fun(n: Int): Boolean {
        if (n > 5) return true
        return false
    }
    println("large: ${numbers.filter(isLarge)}")

    // 10 - 解构 lambda 的参数
    val ages = mapOf("Paul" to 40, "Mélanie" to 35)
    ages.forEach { (name, age) -> println("$name is $age years old") }
}

    • 第 64–68 行：你也可以通过把标签放在左花括号之前来自行选择标签：[odd@{ … }]，然后 [return@odd]；

    val both = display andAlso remember
    both("first")
    both("second")
    println("log: $log")

    val persons = mutableListOf(Person("Paul", 32), Person("Mélanie", 25),
        Person("Jo", 32), Person("Sébastien", 25))
    persons.sortWith(compareBy(Person::age).thenBy(Person::name))
    println("by age then name: $persons")

infix fun <A, B, C> ((A) -> B).then(next: (B) -> C): (A) -> C = { x -> next(this(x)) }

infix fun <A, B, C> ((B) -> C).after(before: (A) -> B): (A) -> C = { x -> this(before(x)) }

// 谓词上的逻辑运算
infix fun <T> ((T) -> Boolean).and(other: (T) -> Boolean): (T) -> Boolean = { this(it) && other(it) }

infix fun <T> ((T) -> Boolean).or(other: (T) -> Boolean): (T) -> Boolean = { this(it) || other(it) }

operator fun <T> ((T) -> Boolean).not(): (T) -> Boolean = { !this(it) }

// 对同一个值连续进行两次处理
infix fun <T> ((T) -> Unit).andAlso(other: (T) -> Unit): (T) -> Unit = { this(it); other(it) }

// 返回函数的函数
fun adder(n: Int): (Int) -> Int = { it + n }

// 保留满足谓词的元素
fun <T> filterElements(elements: List<T>, predicate: (T) -> Boolean): List<T> {
    val result = mutableListOf<T>()
    for (element in elements) {
        if (predicate(element)) {
            result.add(element)
        }
    }
    return result
}

    val exceeds: (Int) -> Boolean = { n -> n > threshold }

    println("variableThreshold=$variableThreshold : exceedsVariable(7)=${exceedsVariable(7)}")

    variableThreshold = 10
    println("variableThreshold=$variableThreshold : exceedsVariable(7)=${exceedsVariable(7)}")

    var total = 0
    val accumulate: (Int) -> Unit = { n -> total += n }
    accumulate(3)
    accumulate(4)
    println("total=$total")
    // 被捕获的变量存储在 Ref 对象中，由 lambda 持有
    println("fields of the lambda: ${accumulate::class.java.declaredFields.map { it.type.name }}")

    count()

    val counterB = createCounter()
    println("A: ${counterA()} ${counterA()} ${counterA()}")
    println("B: ${counterB()} ${counterB()}")

    val actions = mutableListOf<() -> Unit>()

    actions.forEach { action -> action() }
    println()

    7.4. 内联函数与作用域函数

    7.4.1. 内联函数

    lambda 是一个对象。因此，把 lambda 传给高阶函数会产生开销：创建对象（不捕获任何内容的 lambda 除外，虚拟机可以复用它）、调用其[invoke] 方法、泛型接口[Int] ↔ [Integer] 所强制的[Function1]、[Function2]…… 转换，以及被捕获变量的[Ref] 对象。对于像[filter] 这样会在有时非常庞大的集合的每个元素上被调用的函数，这种开销很重要。Kotlin 通过[inline] 修饰符消除了这一开销：当函数被声明为[inline fun] 时，编译器不会生成对该函数的调用；相反，它会把该函数的代码复制到每个调用它的位置，同时也会复制传给它的 lambda 的代码。结果是不再有 lambda 对象，没有[invoke] 调用，也没有转换。接受 lambda 的标准库函数（[forEach]、[filter]、[map]、[fold]、[let]、[apply]、[repeat]、[use]、[synchronized]……）几乎都是[inline]。Java 没有等价机制：它依靠虚拟机的即时编译器来产生与之相当的运行结果。

    代码的插入还有第二个更明显的后果：由于 lambda 的代码被复制到调用函数中，不带标签的[return] 指令可以从那里退出调用函数。这就是非局部返回，我们曾在 *[forEach] 中遇到过，见 *[Lambdas03.kt]。有两个修饰符对 *[inline]* 起补充作用：

    • [noinline]，应用于[inline] 函数的某个函数参数，指定对应的 lambda 不应被复制，而是作为普通对象传递。当函数想要保留该 lambda（把它存入列表、作为结果返回等）时，这是必需的：被复制的代码无法存储在列表中；
    • [crossinline] 要求复制 lambda，但禁止非局部返回。当[inline] 函数本身不执行该 lambda，而是在另一个上下文中执行它时——例如在它创建的[Runnable] 对象中——这是必需的：当[Runnable] 执行时，调用函数可能早已结束，而[return] 将无法再退出它。

// 作用域函数：let、run、with、apply、also（以及 takeIf）

fun main() {
    // 1 - apply：配置对象（this）并返回该对象
    val paul = Person("Paul").apply {
        age = 32
        city = "Angers"
    }
    println("apply: $paul")

    // 2 - also：对对象（it）做额外处理，并返回该对象
    val persons = mutableListOf<Person>()
    val melanie = Person("Mélanie", 25).also { persons.add(it) }
    println("also: $melanie, persons=$persons")

    // 3 - let：将对象（it）转换为一个结果；常与 ?. 搭配使用
    val length = paul.name.let { it.length * 2 }
    println("let: length=$length")
    for (city in listOf("Tours", null)) {
        val message = city?.let { "lives in ${it.uppercase()}" } ?: "unknown city"
        println("let and ?.: $message")
    }

    // 4 - run：对对象（this）进行计算，并返回一个结果
    val description = paul.run { "$name, $age years old, lives in $city" }
    println("run: $description")

    // 5 - with：类似 run，但对象作为参数传入
    val summary = with(StringBuilder()) {
        append("Persons: ")
        append(persons.joinToString { it.name })
        toString()
    }
    println("with: $summary")

    // 6 - takeIf：若对象满足谓词则返回该对象，否则返回 null
    for (age in listOf(15, 40)) {
        val adult = Person("Jo", age).takeIf { it.age >= 18 }
        println("takeIf: ${adult ?: "minor"}")
    }
}

    • 函数类型是默认的选择。它不需要声明，像函数一样被调用，直接接受 lambda 和引用，并且能受益于[inline] 函数。当它很长时，可以用[typealias] 给它起个名字；
    • 当你想要一个真正独立的类型（不会与另一个形式相同的函数混淆）、一个具有描述性名称的方法、带方法体的额外方法，或者一个同样面向 Java 调用方的 API 时，使用“fun”接口是合理的：对 Java 而言，[fun interface] 是一个普通的函数式接口，可以配合其 lambda 使用，而 Kotlin 的函数类型在 Java 看来是一个[Function2<Integer, Integer, Integer>] ，其[invoke] 方法必须返回一个对象（对于“无返回值”的函数，则返回[Unit] ）。

    第二个问题与 Java 中相同：接口应该只有一个方法，还是有多个方法？

    • 函数、函数类型或单方法接口使用起来更灵活：任何形式正确的现有函数都可以使用，而 lambda 甚至允许你直接在调用处编写该函数。无需编写类。这种灵活性解释了为什么现代库（集合、第 9 章中的协程、Spring）大量使用函数参数；
    • 一旦要实现的行为涉及若干相互关联的操作（如上文的[calculate] 和 [name]），或者需要自己的状态和标识，具有多个成员的接口就重新占据优势。

    第 6 章中 [ITaxDao] 接口所在的[dao] 层就是这种情况：尽管它只有一个成员——属性[val taxBrackets: List<TaxBracket>]——但它的实现具有状态（读取的税率档、文件名），由依赖注入容器创建，并在应用程序中代表一个命名清晰的角色。[() -> List<TaxBracket>] 在技术上本来也足够了，但描述性要差得多。因此，我们把函数类型留给简短的一次性行为（一个条件、一次转换、一个动作），而把“业务”接口用于应用程序的角色，无论它们有多少个成员。

    7.6. 事件处理

    7.6.1. 观察者模式

    作为参数传递的函数用于建立事件机制。与 Java 一样，Kotlin 没有专门用于事件的关键字（C# 有自己的关键字[event]）：它使用 Java 早在 1.1 版就为图形组件和 JavaBeans 确立的约定，称为“监听器模型”。[C1] 类想要发出 [Xxx] 事件信号时，按如下步骤进行：

    • [XxxEvent] 类封装有关事件的信息，包括触发事件的对象，称为源。在 Java 中，约定它派生自[java.util.EventObject]，后者存储事件源；在 Kotlin 中，一个带只读属性的普通类就足够了，我们也将这样做；
    • 监听器类型定义事件发生时将被调用的函数的形式。在 Java 中，这是一个名为[XxxListener]的接口；在 Kotlin 中，它通常是一个简单的函数类型[(XxxEvent) -> Unit]，通过[typealias]命名：监听器将是一个 lambda 或函数引用；
    • [C1] 类管理一个函数列表，并提供两个公共方法用于向其注册和注销：[addXxxListener(listener)] 和[removeXxxListener(listener)]；
    • 当[c1] 作为[C1] 的实例想要发出事件信号时，它创建一个 [XxxEvent] 对象，并调用每个已注册的监听器，把这个对象传给它们。按照约定，这种通知由受保护方法[fireXxx(e: XxxEvent)] （“fire”，即触发）处理，派生类可以重写它以修改事件的发布方式；
    • 如果对象[c2] 想要收到来自对象[Xxx] 的事件[c1]的通知，它就使用[c1.addXxxListener(...)]订阅。当它不再希望被通知时，可以通过[c1.removeXxxListener(...)] 取消订阅。由于[c1] 管理的是一个列表，不同的对象可以订阅同一个事件的通知。

    在这个场景中，我们有：

    • 一个发出（也称为“发布”或“发射”）事件的类；
    • 接收此事件通知的对象。它们被称为订阅或注册该事件：它们就是监听器，或事件处理程序；
    • 一种监听器类型，用于定义将收到事件通知的函数的形式。

    这就是观察者设计模式：发射者并不认识它的订阅者；它只是通知它们。这种模型提供的保护与专用关键字相同：监听器列表是发射者的私有属性。从外部只能订阅或取消订阅；无法清空列表、替换其他监听器，或者代替发射者触发事件。

open class Emitter(val name: String) {

        // 触发事件的阈值
        const val THRESHOLD = 19.0
    }

    // 已注册的监听器：一个函数列表
    private val listeners = CopyOnWriteArrayList<TemperatureTooHighListener>()

    var temperature = 0.0
        set(value) {
            field = value
            if (value > THRESHOLD) {
                // 向监听器发出事件信号
                fireTemperatureTooHigh(TemperatureTooHighEvent(this, value))
            }
        }

    // 注册监听器
    fun addTemperatureTooHighListener(listener: TemperatureTooHighListener) {
        listeners.add(listener)
    }

    // 注销监听器
    fun removeTemperatureTooHighListener(listener: TemperatureTooHighListener) {
        listeners.remove(listener)
    }

    // 向所有已注册的监听器通知事件
    protected open fun fireTemperatureTooHigh(e: TemperatureTooHighEvent) {
        for (listener in listeners) {
            listener(e)
        }
    }
}

// 一个注册为事件监听器的类
class Subscriber(
    // 订阅者的名称
    private val name: String,
    // 可接受的最大警报数
    private val nbMaxAlerts: Int,
) {
    // 已收到的警报数
    private var nbAlerts = 0

    // 向发射器注册
    fun subscribe(emitter: Emitter) {
        emitter.addTemperatureTooHighListener(::onTemperatureTooHigh)
    }

    // 注销：对同一对象的同一方法的新引用与原引用相等
    fun unsubscribe(emitter: Emitter) {
        emitter.removeTemperatureTooHighListener(::onTemperatureTooHigh)
    }

    // TemperatureTooHigh 事件的处理程序
    private fun onTemperatureTooHigh(e: TemperatureTooHighEvent) {
        val emitter = e.source
        val temperature = "%.1f".format(e.temperature)
        println("Subscriber [$name]: the source [${emitter.name}] " +
            "signaled a temperature that is too high: [$temperature]")
        // 超过 nbMaxAlerts 次警报后，订阅者注销
        nbAlerts++
        if (nbAlerts == nbMaxAlerts) {
            unsubscribe(emitter)
            println("Subscriber [$name]: unsubscribed after $nbAlerts alert(s)")
        }
    }
}

    • 第 4–11 行：每个订阅者由名称标识，并被指定它所接受的最大警报数（[nbMaxAlerts]）。它对收到的警报进行计数（[nbAlerts]）；
    • 第 14–15 行：向发射者注册。监听器是一个绑定引用[::onTemperatureTooHigh]，即 [this::onTemperatureTooHigh]：这个订阅者的方法 [onTemperatureTooHigh]；
    • 第 19–20 行：取消订阅时，把一个新的引用 [::onTemperatureTooHigh] 传给 [removeTemperatureTooHighListener]。在 Java 中，这会是一个典型的错误：对 ***[this::onTemperatureTooHigh] 求值两次会产生两个被 *[equals] 认为不同的对象，取消订阅将不会移除任何东西，也不会有任何错误消息；监听器必须只创建一次并存储在字段中。我们在[Lambdas04.kt] 中已经看到，在 Kotlin 中，指向同一对象的同一函数的两个引用是相等的：因此[remove] 能找到已注册的监听器——并且只找到该监听器——因为其他订阅者的引用绑定到的是其他对象。对于 lambda 则不然：[{ e -> onTemperatureTooHigh(e) }]**写两次，会得到两个不同的对象；
    • 第 24 行：事件处理程序。它具有由类型[TemperatureTooHighListener]规定的形式。它是私有的：只有订阅者才能把它注册到发射者。另一种做法是让监听器类型由[Subscriber] 类本身实现（[class Subscriber : TemperatureTooHighListener]，带有一个[invoke] 方法），并用[this]进行注册。这种做法的缺点是使[invoke] 方法成为公共方法，任何人都可以调用它；

    7.6.3. 属性变更事件

    最常见的一类事件发生在对象的属性值发生变化时：另一个对象（图形用户界面、缓存、日志）希望收到这一变化的通知。Kotlin 和 Java 库为这种场景提供了两种互补的工具：

    • Kotlin 的委托属性。声明为[var p: T by delegate] 的属性把对其值的读写委托给另一个对象，即委托。标准库提供了其中的几个，例如[by lazy { … }]，它在第一次访问时计算属性的值。对象[kotlin.properties.Delegates] 提供了两个接受 lambda 的委托：[Delegates.observable(initialValue) { property, old, new -> … }] 在每次写入属性之后执行该 lambda；[Delegates.vetoable(initialValue) { property, old, new -> … }] 在写入之前执行它，并且只有当 lambda 返回[true]时才接受新值。参数[property] 是对该属性的引用（[KProperty]），可通过[property.name]获得它的名称；
    • Java 类[java.beans.PropertyChangeSupport]，它为我们管理监听器列表。监听器实现函数式接口[PropertyChangeListener]，其方法[void propertyChange(PropertyChangeEvent evt)] 接收一个事件，其中包含事件源、属性名称及其旧值和新值。

// 一个其属性会发出变更信号的类
class Thermometer(name: String) {
    // 监听器管理委托给一个 PropertyChangeSupport 对象
    private val changes = PropertyChangeSupport(this)

    // 一个可观察属性：每次写入后都会发出变更信号
    private fun <T> observable(initialValue: T): ReadWriteProperty<Any?, T> =
        Delegates.observable(initialValue) { property, old, new ->
            changes.firePropertyChange(property.name, old, new)
        }

    var name: String by observable(name)
    var temperature: Double by observable(0.0)

    // 一个拒绝区间 [5, 30] 之外的值的属性
    var setpoint: Double by Delegates.vetoable(20.0) { _, _, new -> new in 5.0..30.0 }

    // 监听器的注册与注销
    fun addPropertyChangeListener(listener: PropertyChangeListener) {
        changes.addPropertyChangeListener(listener)
    }

    fun addPropertyChangeListener(property: String, listener: PropertyChangeListener) {
        changes.addPropertyChangeListener(property, listener)
    }

    fun removePropertyChangeListener(listener: PropertyChangeListener) {
        changes.removePropertyChangeListener(listener)
    }

    val nbListeners: Int
        get() = changes.propertyChangeListeners.size
}

inline fun <T> List<T>.filterBy(predicate: (T) -> Boolean): List<T> {
    val result = mutableListOf<T>()
    for (element in this) {
        if (predicate(element)) {
            result.add(element)
        }
    }
    return result
}

fun isOdd(n: Int) = n % 2 != 0

// 一个序列中间操作，只放行满足谓词的元素
fun <T> Sequence<T>.keep(predicate: (T) -> Boolean): Sequence<T> = sequence {
    for (element in this@keep) {
        if (predicate(element)) yield(element)
    }
}

// 一个转换每个元素的中间操作：相当于 map
fun <T, R> Sequence<T>.transform(transformation: (T) -> R): Sequence<R> = sequence {
    for (element in this@transform) {
        yield(transformation(element))
    }
}

    • 第 29–34 行：同一个谓词被应用于序列（[asSequence()]）。结果（第 7–8 行）表明，序列的定义不会执行任何操作：第 33 行的消息在第一次测试之前就显示了。只有当终端操作[forEach] 请求元素时，谓词才会执行，并且测试与[forEach]的显示交替进行：每个元素在下一个元素进入之前，都会穿过整个链。这就是序列的延迟（或惰性）执行，与 Java 流相同。序列的中间操作不是[inline]：它们必须保留 lambda，以便稍后执行它们；
    • 第 64–73 行：为了编写我们自己的中间操作——它们像库中的操作一样是惰性的——我们使用序列构造函数[sequence]。它接受一个 lambda，其中函数[yield] 产生序列的一个元素：对于下游请求的每个元素，lambda 都从上次中断的地方继续执行，直到下一个[yield] （这是一个协程，我们将在第 9 章学习这一概念）。[this@keep] 的标签指代扩展函数 [keep]的接收者，即原始序列：如果没有标签，[this] 将表示[sequence]中 lambda 的接收者，因为该 lambda 是带接收者的 lambda。函数 [keep] 只放行满足谓词的元素；函数[transform]是双重泛型的（[T] 是接收到的元素的类型，[R] 是产生的元素的类型），它返回对每个元素应用该函数的结果。Java 24 为同样的目的引入了中间收集器（[Gatherer]），其语法要复杂得多；
    • 第 39–42 行：我们的扩展函数就像库中的操作一样被插入到链中：我们保留至多 5 个字母的城市名，然后把它们转换为大写。终端操作[toList] 触发计算；
    • 第 45–47 行：[generateSequence(1) { it * 2 }] 定义了一个无限序列：1，后面是把前一个元素翻倍得到的每个元素。只有借助惰性求值它才能使用：[take(5)] 只请求前五个元素，并且只计算这些元素。传给[transform] 的 lambda 以[2^n=value] 的形式显示每个幂（[countTrailingZeroBits] 统计二进制表示中最右边的零的个数，即指数）。

    集合和序列上的所有操作都建立在这一模型之上：接受函数类型的高阶函数。对于集合，这些函数是[inline] 且立即执行的；对于序列，它们保留 lambda，并且只在终端操作请求时才计算元素。

    7.8. 表达式树

    一些语言（如 C#）允许把 lambda 转换为数据结构而不是可执行代码，该数据结构描述了这个 lambda（即“表达式树”）：这样程序就可以解析 lambda[t => t.Limit > 20000] 并把它翻译成，例如，由数据库服务器执行的 SQL 子句[WHERE limits > 20000] 。

    Kotlin 与 Java 一样，没有等价物：Kotlin lambda 总是被编译为可执行代码；它可以被调用，但无法检查其内部工作方式。不过，有几种工具与之相近：

    • 属性引用：[Person::age] 是一个对象（[KProperty1<Person, Int>]），它知道属性名称（[Person::age.name]）及其类型。库可以利用这一点来构造查询而无需编写字符串：例如，Spring Data MongoDB 的 Kotlin 扩展就是这样做的，它们允许你写出诸如[Person::age gt 18]这样的条件；
    • 内部DSL （“领域特定语言”）：借助带接收者的 lambda、[infix] 函数和运算符重载，Kotlin 库可以提供类似于 SQL 的语法，程序执行它来构造描述查询的数据结构。这就是 JetBrains 的 Exposed 库背后的原理：[Brackets.selectAll().where { Brackets.limit greater 20000 }]；
    • 编译器插件：Kotlin 编译器可以通过转换代码的插件进行扩展。kotlinx.serialization 就是这样工作的，与 Spring 和 Hibernate 一起使用的[all-open] 和[no-arg] 插件，以及[power-assert] 插件也是如此，后者会分析断言的表达式，以便在失败时显示其详细信息。不过，这些是开发工具，而不是程序的内置功能。

    我们将在第 11 章介绍的 Hibernate 提供了与 Java 中相同的解决方案：一种类似于 SQL、但以类和属性来表达的查询语言，即HQL （["from Bracket t where t.limit > 20000"]），以及 Jakarta Persistence 的Criteria API，它通过方法调用来构造查询（[cb.gt(t.get("limit"), 20000)]）。在这两种情况下，查询都是数据（字符串或对象树），由 Hibernate 翻译成 SQL，而传给[filter] 的 lambda 则是在 Kotlin 程序内部执行的。

    7.9. 结论

    本章的要点：

    • 在 Kotlin 中，函数是值：它们具有函数类型（[(Int, Int) -> Int]、[() -> Unit]、[(T) -> Boolean]、[(() -> Unit)?]、[T.() -> R]……），可以存储在变量中、作为参数传递、作为结果返回，并像普通函数一样被调用。对虚拟机而言，它们是实现接口[Function0]、[Function1]……的对象；
    • [java.util.function] 的接口（[Function]、[Supplier]、[Consumer]、[Predicate]……），以及[Runnable]、[Callable]和[Comparator]仍然可用：当 Java 方法期望函数式接口时，Kotlin 会自动把 lambda 或引用转换成它（SAM 转换）；在其他地方，转换需要显式地写出：[Comparator { … }]；
    • 要给函数类型命名，我们有别名[typealias] （只是一个别名）和[fun interface] （一个真正的新类型，可通过 lambda 实现）；
    • 函数可以通过 lambda 表达式获得（[{ a, b -> a + b }]、[{ it * it }]——当它是最后一个参数时写在圆括号之外，并用[return@label]结束），通过匿名函数，通过匿名对象，或者通过引用（[::function]、[object::method]、[Class::method]、[::Class]）。指向同一对象的同一函数的两个引用是相等的；两个 lambda 永远不相等；
    • lambda 会捕获其周围的变量，包括[var]，并且可以修改它们（编译器把它们存储在[Ref] 对象中）；它们随后看到的是变量在其执行时刻的值，这就要求在循环中和线程之间谨慎处理；
    • 返回函数的函数和函数类型上的扩展（[then]、[and]、[or]……）可以组合出新函数；[compareBy]、[thenBy]和[reversed] 用来构造比较器；
    • [inline] 函数把它们自己的代码和 lambda 的代码复制到调用处，没有对象也没有转换，并且允许非局部返回；[noinline] 和[crossinline] 处理特殊情况。作用域函数[let]、[run]、[with]、[apply]和[also] 是这一机制最常见的应用；
    • 函数类型用于短期的一次性行为；[fun interface] 用于独立的类型，或者可从 Java 使用的 API；多成员接口（或“业务”接口）用于应用程序的角色；
    • 事件通过监听器模式建立：一个 [XxxEvent] 类、一个监听器类型（通常是函数类型的[typealias]）、[addXxxListener] / [removeXxxListener]、以及一个函数列表（[CopyOnWriteArrayList]），由[fireXxx] 方法遍历。委托属性[Delegates.observable] 和[Delegates.vetoable] 发出或过滤属性的变更，而[PropertyChangeSupport] 为它们管理监听器列表；
    • 集合操作（立即执行，[inline]）和序列操作（惰性）都是高阶函数；Kotlin 没有表达式树，Hibernate 使用 HQL 或 Criteria API 来表达其查询。

    lambda 将在后续所有章节中再次出现：线程执行 lambda（[thread { … }]），而 [ExecutorService] 执行一个[Callable] （第 8 章）；协程由[launch { … }] 或[async { … }] 启动（第 9 章），[ResultSet] 的扩展函数将以 lambda 的形式接收把结果中的一行转换为对象的转换逻辑（第 10 章），而 Spring Boot Web 服务在框架作为监听器调用的方法中处理 HTTP 请求（第 13 章）。
